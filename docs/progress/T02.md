  `oapi-codegen/runtime` moved from v1.1.2 to v1.6.0 because `grpc-gateway` v2.30 (pulled in by the OTLP exporters) requires it. Generated code is byte-identical; `make verify-generated` passes.

In v1.43.0, `deployment.environment.name` is an enum key without a helper, so the code uses `semconv.DeploymentEnvironmentNameKey.String(env)`. The attribute is unchanged.
- **go.mod growth:** `go mod tidy` added about 60 `// indirect` lines. These are deps of goose and oapi-codegen, which are imported only from the `tools`-tagged `tools/tools.go` and were never recorded before. No new code enters the API binary; govulncheck scans the default build only.

### Android debug build fixes (both from T09's follow-ups)
- `atlas-mobile/android/build.gradle`: `allprojects { repositories { maven { url = …/async-storage/android/local_repo } } }`. async-storage 3.x ships `org.asyncstorage.shared_storage:storage-android` inside the npm package.
- `atlas-mobile/package.json`: declares `react-native-nitro-modules: 0.31.10`. That version was already installed as react-native-iap's peer. Declaring it makes RN autolinking build it, which react-native-iap 14 (a Nitro module) needs. `npx react-native config` now lists it. The lockfile diff is three lines; no version changed.

- **Unity bridge (Kotlin), the next blocker CI hit after the two fixes above:**
  - `UnityBridgeModule.kt`: RN 0.84 made `ReactContextBaseJavaModule.getCurrentActivity()` a deprecated Kotlin function, so the `currentActivity` property no longer resolves. The code now uses `reactApplicationContext.currentActivity`, RN's own suggested replacement.
  - `UnityBridgeRuntime.kt`: `runOnUiThread { it.finish() }` didn't compile, because a `Runnable` has no `it`. It now calls `finish()` on the captured activity.

  Behaviour is unchanged; Unity stays deferred behind T12's flag.
- **Result:** `Android Debug Build` is green; the log ends `BUILD SUCCESSFUL in 7m 54s, 400 actionable tasks`.

## Deviations from the plan

- **MinIO tag not verified, because MinIO no longer publishes `minio/minio` publicly.**
  - Docker Hub's API returns "object not found" for `minio/minio`, while `minio/mint`, `minio/warp`, `axllent/mailpit` and `library/redis` resolve.
  - `docker manifest inspect` returns "denied: requested access to the resource is denied", unlike the 429 rate limit other images get.
  - quay.io and cgr.dev are blocked on this VM; `mirror.gcr.io` and `public.ecr.aws/bitnami` don't have it.

  MinIO is optional (only for `ASSET_STORAGE_BACKEND=s3|minio`), so I kept it under the optional profile, made the image overridable via `MINIO_IMAGE`, and documented this. Choosing a replacement S3-compatible server is left as a follow-up.
- **govulncheck runs in CI, not on this VM.** The session's egress policy denies `vuln.go.dev` (proxy 403), so I added a permanent `api-vulncheck` CI job. That also gives G19 ongoing coverage. A newly published vuln will turn this job red without any code change; that's intended, and it's a separate job, so the cause is obvious.
- **The Android job builds one ABI** (`arm64-v8a`) to keep it a compile check of reasonable length. T17 owns release APK/AAB builds.
- **Android dependency changes.** Declaring an already-installed peer and adding a Maven repo are config fixes, not the npm upgrades T22 covers.

## Follow-ups found (not fixed)

1. Pick an S3-compatible replacement for local MinIO (for example SeaweedFS, Garage or RustFS), or document an image source the team can access. This also affects `TestS3StorageExistsAgainstMinIO`, which never runs in CI.
2. The deploy job's manifest-bump commit (`chore(staging): deploy atlas-api … [skip ci]`) used to land on main before the Argo sync failed. With the gate off, this stops.
3. The `generated-artifacts` job needs Docker Hub (`sqlc/sqlc`). Anonymous pulls can hit Docker Hub rate limits, as happened on this VM.
4. Bump `google.golang.org/grpc` to v1.85.0 once it's released (GO-2026-6443).
5. Pre-existing lint warnings: three `@typescript-eslint/no-shadow` warnings, already noted in T09.

## How to verify

```bash
cd atlas-api
go version   # go1.26.x (auto-downloaded via the toolchain line if needed)
go build ./... && go vet ./... && gofmt -l . | grep -v generated
ATLAS_TEST_POSTGRES_URL='postgres://atlas:atlas@127.0.0.1:5432/atlas_test?sslmode=disable' go test -count=1 ./...
go run golang.org/x/vuln/cmd/govulncheck@v1.8.0 ./...   # needs access to vuln.go.dev
cd .. && make generate && make verify-generated

docker build -t atlas-api:test atlas-api
docker run --rm --network host -e APP_ENV=local \
  -e POSTGRES_URL='postgres://atlas:atlas@127.0.0.1:5432/atlas?sslmode=disable' atlas-api:test &
curl -fsS http://127.0.0.1:8080/api/v1/health

make dev-up && docker compose -f infra/local/docker-compose.yml ps   # postgres only

cd atlas-mobile && npm ci && cd android && ./gradlew assembleDebug   # needs an Android SDK
```
