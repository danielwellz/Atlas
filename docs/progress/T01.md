## Deviations from the plan

- **The flake also hit Sundays.** The audit said Mondays and Tuesdays. The `now-20d` deadlift fixture is expected in week bucket 3, but on Sundays it lands in bucket 2. The `now-2d`/`now-1d` fixtures (current week plus a 2-day streak) need Wednesday or later. So the fixtures are only valid Wednesday through Saturday. I pinned the clock, which the plan allows, instead of moving every fixture. Moving them would have changed the streak semantics the test asserts. Expected values are unchanged.
- **The clock hook needed a small router refactor.** The test is in package `httpapi_test` and `NewRouter` builds the `Server` internally. `NewRouterWithClock` lives in an `_test.go` file, so it doesn't ship in the binary.
- **CI uses a separate `atlas_test` DB.** Before, CI pointed `ATLAS_TEST_POSTGRES_URL` at the same `atlas` DB that `make api-migrate-up` migrates. The tests then truncated it, including `muscle_groups`, before the new boot step ran. The plan didn't ask for this, but it follows the throwaway-DB rule and keeps the boot smoke test on a clean, migrated DB.
- **The skip guard is broader.** It now matches `skipping integration test`, not just `…: postgres unavailable`, so a missing env var also fails CI.

## Follow-ups found (not fixed, out of scope)

1. `internal/storage` `TestS3StorageExistsAgainstMinIO` skips whenever MinIO is unreachable, and CI has no MinIO service, so it never runs in CI. The CI guard doesn't catch it because its message is `skipping minio integration test`. Either add a MinIO service to CI or decide the test is local-only. It's relevant to T02 (CI hygiene) or to whenever S3 asset storage matters.
2. The "postgres unavailable" skip message prints the full DSN, including the password. It's only test credentials today, but a redacted URL would be safer.
3. `TestDashboardSummaryIncludesFoodLogDailyTotalsIntegration` uses the wall clock, so it could fail if a run crosses UTC midnight between logging food and reading the summary. That's a rare edge case.
4. `semconv` has to track the otel SDK's schema version. T02's dependency bumps should update both together; `otel_test.go` will catch a mismatch.
5. G33's duplicate `seed/` vs `seeds/` CSV is left for T07, as the plan assigns it.

## How to verify

```bash
service postgresql start   # or: docker compose -f infra/local/docker-compose.yml up -d postgres
export POSTGRES_URL='postgres://atlas:atlas@127.0.0.1:5432/atlas?sslmode=disable'

# Migrations on an empty DB, then reset + up
make api-migrate-up POSTGRES_URL=$POSTGRES_URL
cd atlas-api
G='go run -tags "no_clickhouse no_libsql no_mssql no_mysql no_sqlite3 no_vertica no_ydb" github.com/pressly/goose/v3/cmd/goose@v3.24.1 -dir migrations postgres'
eval "$G \"$POSTGRES_URL\" reset" && eval "$G \"$POSTGRES_URL\" up"

# Static checks
go build ./... && go vet ./... && gofmt -l . | grep -v generated   # prints nothing

# Tests against a throwaway DB (no skipped Postgres integration tests)
ATLAS_TEST_POSTGRES_URL='postgres://atlas:atlas@127.0.0.1:5432/atlas_test?sslmode=disable' go test -count=1 ./...

# Without the env var: integration tests skip, dev DB untouched
go test -count=1 ./...

# Boot
go build -o /tmp/atlas-api ./cmd/atlas-api && APP_ENV=local /tmp/atlas-api &
curl -fsS http://127.0.0.1:8080/api/v1/health   # {"status":"ok",...}

# Generated code
cd .. && make generate && make verify-generated
```
