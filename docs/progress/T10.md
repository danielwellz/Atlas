# T10: Mobile token refresh

Status: done (PR open). Gap: G04 (N3).

## What changed

- **`src/api/services/authService.ts`**
  - `refreshAuthTokens(refreshToken)` calls `POST /api/v1/auth/refresh`. It throws `RefreshRejectedError` on 400/401 (the session is over) and `ApiRequestError` on other HTTP errors. A network failure propagates from fetch.
  - `getCurrentUser(accessToken?)` throws `ApiRequestError` with the status. The token argument is now optional because the middleware supplies it.
- **`src/auth/tokenManager.ts`** (new): holds the current tokens in memory.
  - `refreshTokens(staleAccessToken?)` is **single-flight**: concurrent callers share one request. If the current token already differs from the stale one, it returns `refreshed` without a request.
  - Rotated tokens persist through `saveTokens`. A rejected refresh token clears the Keychain and emits `expired`.
  - A session generation counter stops a refresh that finishes after logout or re-login from resurrecting the old session.
  - `getValidAccessToken()` refreshes first when the JWT `exp` (with 30 s skew) has passed.
- **`src/auth/authMiddleware.ts`** (new): openapi-fetch middleware on `atlasApiClient`.
  - Sets `Authorization` from the token manager, overriding stale caller headers.
  - On a 401 it refreshes once and retries the request once, replaying a clone so POST bodies survive. The retry goes straight to `fetch`, so it can't loop.
  - Skips `/api/v1/auth/*`, and does nothing while the manager has no tokens (signed out, mock mode), so caller headers are kept.
  - `installAuthMiddleware()` in `src/auth/index.ts` is idempotent and called when `AuthContext` loads.
- **`src/state/AuthContext.tsx`**
  - Hydrate goes through the token manager. On a 401 from `/me` it confirms with `refreshTokens()` and logs out only if the refresh is **rejected**.
  - A network error, 5xx, or unavailable refresh keeps the session (offline start), using the last profile cached by `src/storage/sessionUserStorage.ts` (AsyncStorage).
  - It subscribes to token changes: `refreshed` updates `session.tokens`, and `expired` logs out.
  - Login and logout go through `startSession` / `endSession`. Logout sends the current, not stale, tokens.
  - Mock mode keeps its tokens out of the manager.
- **`src/sync/outbox.ts`**: `flushOutbox` resolves `getValidAccessToken()` at flush time. The token passed in is now only a fallback when there's no session.
- **`src/api/client.ts`**: resolves `globalThis.fetch` per request, so tests can stub fetch. No runtime behaviour change.
- **Tests** (14 new, all mocking `fetch` with real `Request`/`Response`):
  - `__tests__/auth/token-refresh.test.ts`: expired token → refresh → retry succeeds; POST body replayed; **two parallel requests → exactly one refresh**; refresh 401 → session cleared; refresh network error → session kept; stale caller header replaced; `/auth/*` and signed-out requests untouched; proactive refresh on an expired JWT.
  - `__tests__/auth/auth-hydrate.test.tsx`: **offline hydrate keeps the session**; cold start with an expired access token refreshes instead of logging out; cold start with a rejected refresh token logs out; session tokens follow refreshes and a later rejection logs out; logout uses the current tokens.
  - `__tests__/auth/outbox-token.test.ts`: the flush uses a freshly refreshed token, not the one it was handed.
  - Shared helper: `testUtils/authFetchStub.ts`. It sits outside `__tests__` because Jest treats every file there as a test.

## Deviations from the plan

- **Proactive refresh.** Besides the 401 → refresh → retry path the plan asked for, the middleware refreshes before sending when the access token's JWT `exp` has passed. That saves one failed round trip per expiry and lets the outbox start a flush with a valid token. The 401 path still covers clock skew and opaque tokens.
- **Cached profile for offline starts.** Step 4 says to keep the session on a network error, but a session needs a `User` and `/me` is unreachable. The last profile is cached in AsyncStorage and cleared on logout and expiry. A user with no cached profile (anyone upgrading from a pre-T10 build) who starts offline sees the login screen, but the tokens are **not** cleared, so the next online start restores the session.
- **Service signatures unchanged** (step 3's fallback). Hooks and screens still pass `session.tokens.accessToken`. The middleware overrides it with the current token, and `AuthContext` keeps `session.tokens` updated after refreshes.

## Follow-ups found (not fixed here)

- **T11:** the outbox isn't user-scoped or cleared on logout (G14). Now that logout reliably ends the session, items queued by user A could flush with user B's token after B logs in on the same device.
- Services still take an `accessToken` argument and `assertAccessToken` checks it. Once all callers go through the middleware, the argument could be removed in one sweep.
- The cached profile in AsyncStorage holds email, entitlements, and coach tier (not secret). If that ever matters, move it to the Keychain with the tokens.
- Proactive refresh relies on `atob`, which Hermes and Node provide. Without it the code falls back to the 401 path.

### Manual check with `ACCESS_TOKEN_TTL_MINUTES=1` (done in this session, without a device)

There's no emulator on the dev VM, so I ran the app's real code (API client, auth middleware, token manager, `AuthProvider`) in Jest against a real local API. The test was temporary and is not committed.

1. Booted the API with `APP_ENV=local ACCESS_TOKEN_TTL_MINUTES=1` on a migrated local DB. The issued JWTs had `exp − iat = 60 s`.
2. Logged in through `AuthProvider.applyAuthResponse(loginUser(...))` and loaded `getDashboardSummary`.
3. Waited 125 s, then loaded the dashboard again passing the **stale** `session.tokens.accessToken`, as screens do. It succeeded, and both the access and refresh tokens had rotated.
4. Simulated a restart: unmounted the provider, reset in-memory token state, waited 65 s so the stored access token had expired, and remounted with the last Keychain-saved tokens. Result: hydrated and signed in as the same user, and the dashboard loaded.
