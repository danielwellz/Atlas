# T09: Mobile environment config (API URL per build)

Status: done (PR open). Gap: G05.

## What changed

- **Environment definitions**: `atlas-mobile/src/config/environments.json` defines `local`, `staging`, and `prod`. `local` keeps the old dev hosts (`http://10.0.2.2:8080` on Android, `http://localhost:8080` on iOS and everything else). Staging and prod are `TODO(owner)` placeholders.
- **Build-time selection**: `atlas-mobile/scripts/generate-env.js` writes the gitignored `src/config/env.generated.ts` (environment name plus an optional `ATLAS_API_BASE_URL` override). It exits non-zero on an unknown env, a placeholder, a malformed URL, or a non-HTTPS staging/prod URL, so a misconfigured build fails. It runs:
  - on `npm ci` / `npm install` (`postinstall`), and before `npm test` / `npm run typecheck`, only if the file is missing (`--if-missing`);
  - from Gradle: `generateAtlasEnv<Variant>` runs before `pre<Variant>Build` and `createBundle<Variant>JsAndAssets`;
  - from Xcode: `scripts/xcode-generate-env.sh`, called from the existing "Bundle React Native code and images" phase.
  - by hand: `npm run env` (honours `ATLAS_ENV` and `ATLAS_API_BASE_URL`).
- **Build type → environment**: Android `debug`/`debugOptimized` → `$ATLAS_ENV` or `local`; new `staging` build type (copy of release, `usesCleartextTraffic=false`, `matchingFallbacks=["release"]`) → `staging`; `release` → `prod`. iOS `Debug` → `$ATLAS_ENV` or `local`; `Staging` → `staging`; `Release` → `prod`.
- **Startup fail-fast**: `src/config/index.ts` resolves `appConfig` on first import (imported in `index.js` right after gesture-handler, before the app). `resolveAppConfig` throws `AppConfigError` for a placeholder, an invalid URL, staging/prod without HTTPS, or any plain-HTTP URL when `__DEV__` is false.
- **Shared rules**: `src/config/apiBaseUrlRules.js` (plain CommonJS) is used by both the generator and the app, so build-time and run-time checks can't drift.
- **API client**: `src/api/client.ts` takes `baseUrl` from `appConfig.apiBaseUrl`. The `API_BASE_URL` export is gone; its only other user was the biomechanics service.
- **Biomechanics**: `src/api/services/biomechanicsService.ts` now calls `atlasApiClient.GET('/api/v1/exercises/{id}/biomechanics')` and uses the generated schema types instead of hand-written duplicates.
- **Docs**: an "Environments (API base URL)" section in `atlas-mobile/README.md`.
- **Tests**: `__tests__/config/app-config.test.ts` (resolution, prod rejects `http://`, release rejects HTTP, placeholders), `__tests__/config/generate-env.test.ts` (generator), `__tests__/services/biomechanics-service.test.ts`.

## Deviations from the plan

- **No `react-native-config`.** I used the plan's native-free option: a generated TS module, no native dependency, nothing to check for New Architecture compatibility.
- **Defaults live in JSON, not in the generated file.** The generated file only records the environment name and an optional override. That way the owner can commit public URLs to `environments.json` or inject them from CI secrets, and the acceptance grep only matches `environments.json`.
- **iOS `Staging` configuration not created.** The owner decided no iOS effort for now (T18 skipped). Adding a build configuration means hand-editing several `project.pbxproj` sections, which can't be checked without Xcode. The build-phase script already maps `Staging`. The only pbxproj change is two lines inside the existing bundle phase's `shellScript`.
- **The generator also fails the build.** The plan only asked for a startup check. Failing at build time is cheaper, and the startup check stays as a backstop.
- **Consequence:** `./gradlew assembleRelease` and `assembleStaging` (and iOS Release archives) **fail until a real HTTPS URL is provided**. This is intentional, but T17/T18 CI release builds must pass `ATLAS_API_BASE_URL` (or the owner must fill in `environments.json`).

## Follow-ups found (not fixed here)

- **For T02: Android debug build is broken before any T09 code runs.** On a GitHub runner (JDK 17, Node 22, `npm ci`), `cd atlas-mobile/android && ./gradlew assembleDebug` fails with:
  ```
  Could not determine the dependencies of task ':app:compileDebugJavaWithJavac'.
  > Could not resolve all dependencies for configuration ':app:debugCompileClasspath'.
     > Could not find org.asyncstorage.shared_storage:storage-android:1.0.0.
       Required by:
           project ':app' > project :react-native-async-storage_async-storage
  ```
  `@react-native-async-storage/async-storage` 3.x ships that artifact in `node_modules/@react-native-async-storage/async-storage/android/local_repo`, and the app must add the repo. This fix, appended to `atlas-mobile/android/build.gradle`, resolved the error on the throwaway verification branch:
  ```groovy
  allprojects {
      repositories {
          maven { url = uri("${rootDir}/../node_modules/@react-native-async-storage/async-storage/android/local_repo") }
      }
  }
  ```
- **For T02 (next blocker after that fix):** `:react-native-iap:compileDebugKotlin` fails with `Unresolved reference 'Promise'` / `Unresolved reference 'Ni…'` in `node_modules/react-native-iap/nitrogen/generated/android/kotlin/com/margelo/nitro/iap/HybridRnIapSpec.kt` and `.../HybridRnIap.kt`. react-native-iap 14 is a Nitro module and needs `react-native-nitro-modules` as a direct app dependency, so autolinking adds it; today it's only a transitive dependency. The paywall is off for 1.0, so removing react-native-iap is another option.
- The Android `staging` build type shares the release `applicationId`, so it replaces a release install on the same device. Consider `applicationIdSuffix ".staging"` together with T17's final IDs.
- iOS `Staging` build configuration (T18, currently skipped).
- All variants share one generated file, so `./gradlew assembleStaging assembleRelease` in a single invocation would race. The README says to build one non-debug variant per invocation. A per-variant generated file (via a Metro resolver) would remove this limitation if it matters.
- After building staging/release locally, Metro keeps serving that environment until `npm run env` or a debug build regenerates `local`. This is documented.
- Pre-existing lint warnings: `@typescript-eslint/no-shadow` for `React` in three integration tests.
- Pre-existing: Jest reports "A worker process has failed to exit gracefully" (a leaked handle in some existing test).

## How to verify

```sh
cd atlas-mobile
npm ci                     # prints "[atlas-env] local -> src/config/env.generated.ts"
npm run lint && npm run typecheck && npm test -- --watchAll=false
grep -rn "10.0.2.2\|localhost:8080" src           # only src/config/environments.json
node scripts/generate-env.js --env prod           # fails: placeholder
ATLAS_API_BASE_URL=http://x.test node scripts/generate-env.js --env prod     # fails: must use https
ATLAS_API_BASE_URL=https://x.test node scripts/generate-env.js --env prod    # ok
npm run env                                       # back to local
# With an Android SDK (full APKs need the T02 fixes above first):
cd android && ./gradlew assembleDebug
ATLAS_API_BASE_URL=https://api.staging.example.com ./gradlew assembleStaging
```
